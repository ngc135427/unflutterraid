# File Browser 设置与共享卡片精简

## Goal

让 File Browser 连接地址可以在设置中修改并持久化，避免当前固定使用 Unraid 主机的 `8080` 端口而导致文件浏览、预览和备份无法连接；同时精简共享文件夹卡片，移除无价值的原始字段和重复操作按钮。

## Background

- 当前代码没有 WebDAV 协议实现；文件浏览使用 `UnraidFileManager` 调用 File Browser HTTP API。
- `UnraidApiClient` 已支持可选的 `fileBrowserBaseUrl` 构造参数，但登录、服务器配置和服务器档案连接入口都没有传入该参数。
- 未显式传入时，文件服务地址固定派生为 Unraid 主机同协议、端口 `8080`。
- 过去的项目决定是先采用“官方 Unraid API + File Browser”作为 MVP，WebDAV 当时被列为非必需能力。
- 共享卡片整体已经可点击并进入文件浏览；卡片底部的“浏览”和“设置”按钮当前执行相同操作。
- `include []`、`exclude []` 和类似 `0` 的值来自共享元数据标签，对当前移动端浏览场景没有有效信息。

## Requirements

- 在设置页提供独立的 File Browser 连接配置入口，允许填写完整的 `http://` 或 `https://` 基础 URL（包括自定义端口和反向代理路径）。
- 配置按 Unraid 服务器地址分别保存，并在应用重启、切换服务器和页面导航后保留。
- 新配置必须实际用于后续文件列表、预览、读取和备份请求，而不只是展示在设置页。
- 未配置时保持现有的同主机 `8080` 默认行为，兼容已有用户。
- 所有新增界面文案同时支持简体中文和英文。
- 本次不新增 File Browser 用户名或密码；继续使用现有匿名访问或反向代理鉴权方式。
- 共享文件夹卡片不再显示标签区域，包括 `include []`、`exclude []`、`0` 等原始元数据。
- 共享文件夹卡片不再显示“浏览”和“设置”按钮；点击卡片任意位置仍进入对应文件夹浏览。
- Docker 和虚拟机卡片的标签、操作按钮与行为保持不变。

## Acceptance Criteria

- [x] 用户可以从设置页查看和修改文件服务地址。
- [x] 保存后重新进入应用仍能读取配置。
- [x] 登录、服务器配置重连和服务器档案连接创建 `UnraidApiClient` 时使用对应服务器已保存的文件服务配置。
- [x] 留空配置时仍使用当前默认地址派生规则。
- [x] 文件服务设置拒绝无效或非 HTTP(S) URL，并提供明确的保存反馈；保存后当前会话立即使用新地址。
- [x] File Browser 基础 URL 含反向代理路径时，现有 `/api/...` 请求仍正确拼接。
- [x] 共享文件夹卡片不再出现标签、“浏览”或“设置”，点击卡片仍进入文件浏览。
- [x] Docker 和虚拟机卡片 UI 不受共享卡片精简影响。
- [x] 相关单元或组件测试通过，`flutter analyze` 无新增问题。
- [x] 生成可安装的 Android Release APK，并提供产物路径。
- [x] 仅提交本任务相关源码与 Trellis 任务记录，并推送当前分支。

## Out of Scope

- 新增真正的 WebDAV 协议、WebDAV 用户名/密码或协议选择器。
- 改动 GraphQL 的共享字段查询或服务端共享配置。
- 移除共享标签底层数据；仅从共享卡片展示中隐藏，保留现有映射和搜索行为。
