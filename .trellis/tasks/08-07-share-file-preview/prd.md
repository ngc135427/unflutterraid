# 共享文件预览优化

## Goal

让用户在共享文件浏览器中直接确认文件内容，减少下载到本地或切换到其他应用的次数，同时避免大文件预览导致明显卡顿或内存压力。

## Confirmed Facts

- 共享文件浏览器位于 `lib/pages/main_shell_page.dart:2823`，当前点击目录会进入下级目录。
- 当前只有图片点击后会打开预览；其他文件统一提示不支持预览（`lib/pages/main_shell_page.dart:3062`）。
- 图片预览会通过 `readFileBytes` 一次性加载原文件到内存（`lib/pages/main_shell_page.dart:4007`），大图存在等待时间和内存占用风险。
- File Browser 客户端已经提供原文件 URL、原文件字节读取和缩略图读取能力（`lib/services/unraid_api_client.dart:275`、`:300`、`:307`）。
- 文件模型已经识别图片、视频和音频扩展名（`lib/services/unraid_api_client.dart:1399`）。
- 项目已有 `just_audio`，尚未引入视频或 PDF 预览依赖（`pubspec.yaml:19`）。

## Requirements

- R1：保留现有目录浏览、选择、重命名、删除、复制和移动行为。
- R2：预览入口应根据文件类型显示正确图标和可预览状态；不支持的类型必须给出明确反馈。
- R3：图片预览应优先使用较小的预览资源，避免打开预览时无条件下载完整原图。
- R4：预览必须包含加载、失败、关闭状态，并显示当前文件名。
- R5：新增用户可见文案必须同时提供中文和英文。
- R6：首版支持图片、视频、音频、常见文本和 PDF 文件预览。
- R7：Office 文档与压缩包不提供预览能力。
- R8：视频与音频在应用内播放，提供播放/暂停、进度拖动和时长显示；视频支持全屏。
- R9：文本预览最大读取 2 MB；超过上限时不完整加载，并显示文件过大提示。
- R10：预览器支持按钮和左右滑动切换同一目录中的上一个/下一个可预览文件；切换时自动暂停当前媒体。
- R11：媒体默认不自动播放；用户主动播放后，离开预览或切换文件必须停止播放并释放资源。
- R12：图片先显示缩略预览；只有用户主动选择查看原图时才读取完整原文件。
- R13：功能覆盖项目当前支持的移动端、桌面端和 Web 平台；平台不支持的具体媒体编码应显示播放失败，而不是导致页面崩溃。

## Acceptance Criteria

- [ ] 点击受支持文件可以在共享浏览流程内查看或播放内容。
- [ ] PDF 可以在应用内打开并翻页查看。
- [ ] 音频和视频无需跳转外部应用即可播放、暂停和拖动进度。
- [ ] 视频可以进入和退出全屏，退出后仍能安全释放播放器资源。
- [ ] 不超过 2 MB 的受支持文本文件可读取查看；超限文件不会被完整加载。
- [ ] 用户可以通过按钮或左右滑动连续预览同一目录中的受支持文件。
- [ ] 切换离开音频或视频时，原媒体不会继续后台播放。
- [ ] 大图片打开预览时不再首先完整读取原文件字节。
- [ ] 加载失败时显示可理解的错误，用户可以关闭预览并继续浏览当前目录。
- [ ] 原有共享文件管理操作不回退。
- [ ] 中英文界面没有新增硬编码文案。
- [ ] `flutter analyze` 与相关测试通过。

## Out of Scope

- 编辑文件内容。
- Office 文档预览或编辑。
- 压缩包预览或解压。
- 修改相册页面现有预览器。
- 为不受播放器支持的编码实现转码。
